# PRISM — Security & Privacy

---

## Scope

PRISM is a hackathon MVP. This document defines minimum-viable security and privacy practices. Production deployment would require a full security audit.

---

## 1. Uploaded Files

| Concern | Policy |
|---------|--------|
| **Accepted formats** | PDF (application/pdf) and plain text (text/plain) only |
| **File size limit** | 10 MB maximum |
| **Text length limit** | 25,000 characters maximum |
| **File storage** | Files are NOT stored on disk. PDF content is extracted in memory and discarded after extraction. Only the extracted text is persisted (in SQLite). |
| **Validation** | MIME type check, file size check, magic bytes validation for PDF |
| **Malicious content** | PDF.js runs in Node.js (not browser), limiting attack surface. No JavaScript execution from uploaded PDFs. |
| **Cleanup** | Uploaded file buffers are released after extraction completes |

## 2. Learner Behavioral Data

| Data | Storage | Retention | Sensitivity |
|------|---------|-----------|-------------|
| Dwell time (per concept) | SQLite | Session duration + 7 days | Low |
| Reread count | SQLite | Session duration + 7 days | Low |
| Scroll-back events | SQLite | Session duration + 7 days | Low |
| Help request count | SQLite | Session duration + 7 days | Low |
| Question accuracy | SQLite | Session duration + 7 days | Low |
| Answer latency | SQLite | Session duration + 7 days | Low |
| Retry count | SQLite | Session duration + 7 days | Low |
| Voice help requests | SQLite | Session duration + 7 days | Low |
| Struggle score | SQLite | Session duration + 7 days | Low |
| Adaptation history | SQLite | Session duration + 7 days | Low |

**Important:** Behavioral data is used ONLY for real-time adaptation within the session. It is NOT:
- Shared with third parties
- Used for advertising or profiling
- Used for clinical diagnosis
- Aggregated across users (no user accounts in MVP)

## 3. Voice Data

| Data | Storage | Retention | Notes |
|------|---------|-----------|-------|
| Audio input | NOT stored | Discarded immediately | Processed by browser's Speech Recognition API only |
| Voice transcript | In-memory only | Current session only | Used for intent routing, not persisted |
| TTS output | NOT stored | Discarded after playback | Generated by browser, not recorded |

**Important:**
- No audio is recorded, stored, or transmitted to PRISM servers
- Web Speech Recognition API may use cloud-based processing (browser-dependent, Google for Chrome)
- PRISM does not control or access the audio stream directly
- Microphone access requires explicit user permission via browser native dialog

---

## 5. Data Retention

| Data | Retention Policy |
|------|-----------------|
| Uploaded document text | Until session cleared or 7 days, whichever is first |
| Learner profile | Persists indefinitely (until manually deleted) |
| Session/signal data | 7 days after last activity |
| Adaptation history | 7 days after last activity |
| LLM cached outputs | Persists with document (until document deleted) |

**Cleanup:** A scheduled cleanup function removes sessions older than 7 days on server start:

```javascript
function cleanupOldSessions() {
  const cutoff = new Date(Date.now() - 7 * 24 * 60 * 60 * 1000).toISOString();
  db.prepare('DELETE FROM learning_sessions WHERE last_activity_at < ?').run(cutoff);
  db.prepare('DELETE FROM learner_signals WHERE recorded_at < ?').run(cutoff);
  // Cascade deletes handle related records
}
```

## 6. Consent

- **Microphone:** Browser-native permission dialog. PRISM does not auto-activate the microphone.
- **Data collection:** MVP does not include a formal consent dialog (hackathon scope). Production would require a privacy notice and opt-in consent.
- **Cookies:** PRISM does not use cookies. No tracking cookies, no analytics cookies.

---

## 7. API Security

| Measure | Status | Notes |
|---------|--------|-------|
| HTTPS | Required in production | Vercel/Render provide automatic SSL |
| CORS | Restricted to frontend origin | `CORS_ORIGIN` env var |
| Rate limiting | Not implemented (MVP) | Future: express-rate-limit |
| Authentication | Not implemented (MVP) | No user accounts |
| Input validation | Zod schemas on all endpoints | Reject malformed requests |
| SQL injection | Protected | better-sqlite3 uses parameterized queries |
| XSS | Protected | React auto-escapes output; no `dangerouslySetInnerHTML` |
| CSRF | Not applicable | No session cookies, no authentication |
| File upload validation | MIME type + size check | Reject non-PDF files |

## 8. File Restrictions

| Restriction | Value |
|-------------|-------|
| Maximum file size | 10 MB |
| Allowed MIME types | `application/pdf`, `text/plain` |
| Maximum text length | 25,000 characters |

---

## 9. No Diagnosis Storage

**PRISM does NOT store:**
- Medical diagnoses
- Learning disability classifications
- Clinical assessment results
- IEP (Individualized Education Program) data
- Psychological evaluations

**PRISM DOES store:**
- Profile type preference ("dyslexia", "low_vision", "cognitive_load", "custom")
- This is a **UI preference**, not a medical record
- It controls typography and formatting, not clinical treatment

---

## 10. AI Data Handling

| Concern | Policy |
|---------|--------|
| **Data sent to OpenAI** | Document text + system prompts. No learner personal data sent. |
| **OpenAI data retention** | Subject to OpenAI's API data usage policy (API data not used for training by default) |
| **Prompt injection** | System prompts use instruction framing. User text is clearly separated as `[USER CONTENT]`. |
| **LLM output validation** | All LLM outputs validated against Zod schemas before storage |
| **Fallback on LLM failure** | Deterministic fallback — no data is lost |

### Data sent to OpenAI (per request):

```
System prompt (fixed template)
User content: document text only
```

**NOT sent to OpenAI:**
- Learner profile data
- Behavioral signals
- Session state
- Voice transcripts
- Personal information (there is none — no user accounts)

## Production Security Recommendations (Post-Hackathon)

1. Enable HTTPS everywhere
2. Add rate limiting (express-rate-limit)
3. Add authentication (if user accounts added)
4. Encrypt SQLite database at rest
5. Add formal privacy notice and consent dialog
6. Implement data export/deletion API (GDPR-like)
7. Add request logging with audit trail
8. Security headers (Helmet.js)
9. Regular dependency audits (`npm audit`)
10. Penetration testing
